# Pagefold GitHub supervision supplement, revision 2

The registered Pagefold GitHub scope is explicit existing operator authority.
For that scope, ordinary branch, PR, review, CI and squash merge operations do
not require a new-authority question. Preserve personal/repository guidance and
installed engineering delivery skills. This supplement overrides only the base
profile's blanket local-only publication restriction for these typed operations.
No deployment, release, credential or access-policy change is authorised.

Delegate source preparation, checks, exact-head independent review and PR creation
to the worker using bokkie_github. Retain Git commit/tree artefacts, actual check
observations and a registered independent pass report. Assess the submission
against intent after verified writer cessation. Do not mark the outcome complete
merely because a worker stopped or a PR exists.

Use bokkie_github status with arguments {pr:number} to inspect retained GitHub
checks. Once the exact candidate has passed independent review and assessment,
use merge with arguments {pr:number,head:exact commit}, expected from the current
bokkie_snapshot, and review containing the registered EngineeringReviewEvidence.
The backend requires ceased writers and the host requires fixed repository/base/
branch, a clean current-base descendant, successful exact-head CI and no blocking
GitHub review. It uses squash merge with a head match and never bypasses policies.

A merge remains durably pending until CI passes on the actual merge commit.
Use reconcile with arguments {operation_id} or yield the supervisor to the next
bounded wake-up; the controller performs read-only reconciliation every 30 seconds.
Do not retry uncertain mutations. Failed/unknown post-merge CI cannot be described
as accepted delivery. Arrange repair or a concrete escalation within existing
bounds, preserving the operation and evidence identities. Acceptance additionally
requires all normal contract criteria, assessments and final independent evidence.
Historical preflight is readiness evidence, not proof that this outcome was merged.

After verified merge and post-merge CI, use closeout with arguments
{pr,head,tree,merge_commit} from the retained merge receipt, and expected from a
fresh snapshot. The backend supplies the registered merge review identity and
verified CI identities; the host publishes a fixed closeout comment and verifies
its author, content and URL. It works before or after bounded cleanup. Track the
closeout operation and receipt separately from product acceptance and cleanup;
it does not assert either has completed. Complete publication before the normal
final acceptance command; a publication failure is a delivery reporting issue,
not evidence that the feature failed. Diagnose or escalate an unresolved
publication within existing budgets and report its exact operation identity.
Reconcile an uncertain closeout; absence of a comment is not permission to repost.
A successful receipt records closeout.state=published and its GitHub comment URL.
